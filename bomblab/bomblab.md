## phase_1  
```
0x555555555607<phase 1>             endbr64
0x55555555560b<phase 1+4>           sub     $0x8,%rsp
0x55555555560f<phase 1+8>           mov     0x1cba(%rip),%rsi
0x555555555616<phase 1+15>          0x555555555af4<strings not equal>
```
使用gdb调试，在phase_1处设置断点，输入随机一个字符串`abc`，然后发现在`0x555555555616<phase 1+15>`处判断字符串是否相等处传入两个参数`%rdi`和`%rsi`，在调试过程中对`%rsi`的值进行输出，使用指令：
```
p (char *)($rsi)
```
使用同样方法亦可得`%rdi`的值为`abc`，即为输入串  
可得答案为`The future will be better tomorrow.`

```

a=1时，地址%rax=0x555555555745，对应：mov  $0x19b,%eax，即411

a=6时，地址%rax=0x55555555572b，对应：mov  $0x177,%eax，即375  
a=7时，地址%rax=0x555555555732，对应：mov  $0x35d,%eax，即861  
```
在对`%eax`赋值后，经过
```
    16f4:	39 44 24 04          	cmp    %eax,0x4(%rsp)
    16f8:	75 52                	jne    174c <phase_3+0xaf>
```
由`%eax`的值来判断第二个数是否正确，若不正确则调用`explode_bomb`函数。  
因此，对于不同的输入a，其对应的第二个数为：
```
a=0时，第二个数是216  
a=1时，第二个数是411  
a=2时，第二个数是674  
a=3时，第二个数是988  
a=4时，第二个数是991  
a=5时，第二个数是427  
a=6时，第二个数是375  
a=7时，第二个数是861  
```
因此，答案为`0 216`（或其中任意一对）。
## phase_4  
类似于前面的方法，可以推知题目要求按照 `%d %d` 的格式读入2个数字。  
phase_4的调用函数fun4  
```
    1768:	d1 fb                	sar    %ebx
    176a:	01 f3                	add    %esi,%ebx
```
这两句其实就等价于计算了$\frac{\text{\%edx} + \text{\%esi}}{2}$  
```
    176e:	7f 06                	jg     1776 <func4+0x1e>
    1770:	7c 10                	jl     1782 <func4+0x2a>
    1772:	89 d8                	mov    %ebx,%eax
    1774:	5b                   	pop    %rbx
    1775:	c3                   	ret    
    1776:	8d 53 ff             	lea    -0x1(%rbx),%edx
    1779:	e8 da ff ff ff       	call   1758 <func4>
    177e:	01 c3                	add    %eax,%ebx
    1780:	eb f0                	jmp    1772 <func4+0x1a>
    1782:	8d 73 01             	lea    0x1(%rbx),%esi
    1785:	e8 ce ff ff ff       	call   1758 <func4>
    178a:	01 c3                	add    %eax,%ebx
    178c:	eb e4                	jmp    1772 <func4+0x1a>
```
这些代码比较了第一个输入的数与先前计算的中间值的大小关系，并使用二分查找缩小区间来递归，最后还将每一次的返回值相加。  
```
    17d7:	e8 7c ff ff ff       	call   1758 <func4>
    17dc:	83 f8 0d             	cmp    $0xd,%eax
    17df:	75 07                	jne    17e8 <phase_4+0x5a>
    17e1:	83 7c 24 04 0d       	cmpl   $0xd,0x4(%rsp)
    17e6:	74 05                	je     17ed <phase_4+0x5f>
```
可知，只有当func4函数的返回值为13且第二个输入的数也是13时，才能不引爆炸弹  
在func4函数中推理易得输入的第一个数应该是2  
综上，答案应该为`2 13`。
## phase_5  
由汇编代码可以推知题目要求输入一个长度为6的字符串  
```
    182c:	0f b6 10             	movzbl (%rax),%edx
    182f:	83 e2 0f             	and    $0xf,%edx
    1832:	03 0c 96             	add    (%rsi,%rdx,4),%ecx
    1835:	48 83 c0 01          	add    $0x1,%rax
    1839:	48 39 f8             	cmp    %rdi,%rax
    183c:	75 ee                	jne    182c <phase_5+0x25>
    183e:	83 f9 3a             	cmp    $0x3a,%ecx
    1841:	75 09                	jne    184c <phase_5+0x45>
```
对于输入的每一个字符，使用`and    $0xf,%edx`对字符的ascii码进行16取模，然后以此为索引在内存array数组中寻找到每一个字符对应的数字，并累加起来。  
要求字符的累加结果为58才不会引爆炸弹  
以下是对内存array数组的寻找过程：  
在动态编译过程中，可以看到array数组的起始地址为：`0x5555555574e0`  
因此对于每一个`index`，其对应的数组元素的地址为：`0x5555555574e0 + index*4`  
因此可以通过`p *(int *)(0x5555555574e0+index*4)`来查看每个元素的值。  
以下为这个长度为16的数组的每一个值：  
$$
a_0=2,a_1=10,a_2=6,a_3=1,a_4=12,a_5=16,a_6=9,a_7=3,a_8=4,a_9=7,a_{10}=14,a_{11}=5,a_{12}=11,a_{13}=8,a_{14}=15,a_{15}=13
$$
在这16个数中，可以找到6个数的和为58，$6+16+3+4+14+15=58$  
对应的索引为：$2,4,5,7,8,14$  
对应ascii码，可以找到对应的字符为：`b,e,g,h,j,n`  
答案为`beghjn`。
